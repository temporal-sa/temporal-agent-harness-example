P3 · U0 wireframes · for owner review

The coding agent product view

These frames walk the 7-minute demo script on the refund bug, at 1920 × 1080 (screen share), 1366 × 768 (laptop) and 320 px (phone). They are drawn with the buildkit theme so you can judge the look as well as the layout. Every number and line of copy is what the build would show for that beat. No UI code exists yet.

PRD v1.2 · U0–U8, §2.5 Data: harness events + observable state + x_usage / x_recovery No Queries from the browser Yellow numbers are review notes, not UI

What I need from you

Four layout choices. The frames show my recommendation for each.

Reply /yes to approve the frames as drawn, or tell me which choice to change (for example "2b"). Copy and spacing will still get a review pass during the build.

1 · Workbench placement Where do Plan, Changes, Terminal and Artifacts live?
1a ✓ A right-hand panel beside the transcript, like Cursor. Both stay visible on a screen share. 1b A bottom drawer under the transcript. More width for chat, but the terminal competes with the composer.
2 · Session sidebar How much room do past sessions get?
2a ✓ Full list at 1920. At 1366 and in presenter mode it collapses to an icon rail. 2b Always collapsed, opened from the header menu.
3 · Backdrop How much of the buildkit space backdrop?
3a ✓ The hero gradient only. No starfield or grid floor, so motion only ever means a state change. 3b Starfield and grid floor behind the sidebar and header, with a pause control.
4 · Meters Where does the token, cache and recovery strip sit?
4a ✓ A strip under the header, always visible. After the first recovery its first number becomes the green "work kept" figure. 4b In the composer footer. Quieter, but off-screen in the audience's eye line.

Frame 1 · 0:40 – 1:50 in the script

Working: explorers, the fix, the judge, the test run

1920 × 1080 · scaled to fit
  1. Header. Session status as a pill (Running, Worker isn't answering, Waiting for you, Idle). The three view links carry their captions: what your users see, the agent loop as the harness records it, the Workflow history. Console and Temporal UI open on this session.
  2. Meters strip. Session tokens in and out, the share of input read from the provider's cache, and recoveries. Missing usage reads "not reported", never 0.
  3. Thinking. Collapsed to "Thought for 12s". It shows tokens only when the provider reports them.
  4. Explorers. The two subagents run side by side as nested rows, each with its question, its tool calls and its findings. beat 0:40
  5. Edit with inline diff. Deletions are pink with a strikethrough and additions green. Red is never used for a diff. Path chips open the file in Changes. beat 1:50
  6. Judge card. In Auto mode the judge's verdict sits above the tool it decided, with its confidence and a one-line reason.
  7. Live command row. It shows elapsed time and the latest output line. The full stream is in Terminal.
  8. Workbench. The tabs show counts and a live dot. Terminal colors stdout off-white and stderr indigo, and a failing exit is a yellow badge ("exit 1 · tests failing").
  9. Composer. The model picker and posture sit in the composer. Stop replaces Send while a turn runs (Esc). Text typed mid-turn offers "Steer now" or "Queue".

Frame 2 · 2:40 · worker killed during the test run

Worker isn't answering

1920 × 1080 · scaled to fit
  1. Status turns yellow. The banner comes from the bridge going quiet plus a Describe of the Workflow, never a Query, so it works with every worker down.
  2. Banner copy says what is saved and what is waiting, and links to the pending Activity in Temporal UI for the presenter's next click.
  3. The command row stops its clock and says what it is waiting for. Nothing on screen claims an error.
  4. Terminal keeps the output it already has and marks where the stream paused.
  5. Composer stays usable. A message sent now shows "In Temporal, waiting for a worker" and applies when a worker returns (P2 step 2.2b).

Frame 3 · 2:40 – 4:00 · another worker finishes the turn

Recovered: the divider and the "work kept" meter

1366 × 768 · scaled to fit
  1. Hero meter. After the first recovery the first number becomes "Work kept after worker loss (this session)", in the green gradient. Each figure is confirmed against Workflow history; until then it reads "Checking…".
  2. Recovery divider at the point in the turn where the worker was lost. The ⓘ explains the comparison: "compared with re-running this turn from your message".
  3. Repeated work is named honestly (1 model call, attempt 2). The partial text from attempt 1 folds under "Attempt 1 (worker lost)", so nothing is duplicated.
  4. 1366 layout. The sidebar collapses to a rail, and the workbench narrows to 30 em.
  5. Terminal shows the reattached run finishing: "exit 0 · 27 passed".

Frame 4 · 4:10 · after a page reload

Waiting for you: the commit needs a human

1366 × 768 · scaled to fit
  1. Pink means the agent is waiting on a person, both in the status pill and on the card.
  2. Escalation from the judge or the pre-rules says why in one line. Commits always go to a human in the catalog.
  3. Decision card above the composer, with the exact arguments. "Always allow" appears only for file edits, so it is absent here.
  4. The paused line: "The agent is paused in Temporal and nothing is running." This card came back after a reload.
  5. Send states after a click: Sending → In Temporal → Accepted → Running. Accepted renders within 100 ms.
  6. Changes tab shows the full unified diff the commit will contain.

Frame 5 · 4:50 · switch to GPT and ask for a review

Same chat, another provider, a structured review

1920 × 1080 · scaled to fit
  1. Model switch line in the transcript: "Model changed to GPT-5.5 (OpenAI). Applies from this turn." The picker acknowledges within 100 ms and says "applies next turn" until then.
  2. Reviewer subagent returns its typed Review as a card: a verdict and issues, each with severity and file:line.
  3. Thinking on GPT shows "Reasoning summary not provided by OpenAI" when there is no summary text.
  4. Meters keep one session total across providers. The cache figure shows each provider's own cache reads.

Frame 6 · phone

320 px: transcript first, workbench as a sheet

320 × 690 · actual size
  1. One column. Sessions open from the menu. The view links move into it as well.
  2. Meters collapse to one line of three numbers.
  3. Tool rows keep the badge and name and drop the argument preview. Tapping a row opens it.
  4. "Changes (1)" opens the workbench as a bottom sheet with Plan, Changes, Terminal and Artifacts. Tap targets are at least 44 px and nothing scrolls sideways.
